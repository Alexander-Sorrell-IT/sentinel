# SENTINEL — Design Spec

**UiPath AgentHack · Track 3 (UiPath Test Cloud) · solo build · ~5-week window**
**Status:** design locked via adversarial review (red-team + clean-slate + judge). Pre-credentials. Confidence levels marked: **[CONFIRMED]** = verified in docs, **[ASSUMED]** = plausible, unverified, **[DAY-1]** = must verify the moment Labs access lands.

---

## 1. One-line

> Sentinel is an agentic test harness that validates the quality and reliability of AI-infused workflows — adversarially probing whether their built-in governance controls actually hold before an agent acts on production business systems.

---

## 2. The problem (Business Impact)

Enterprises are putting AI agents into real business processes. Two gaps make that dangerous, and neither is closed by current tooling:

1. **UiPath 2025.10 ships *detective* guardrails for agents — but no shipped way to *prove* they actually fire.** [CONFIRMED] You can configure a guardrail; you cannot run a suite that demonstrates it catches the thing it's supposed to catch.
2. **Native evaluators score *correctness* and *behavior*, not *policy conformance*.** [CONFIRMED] An agent can produce an output that looks correct to an LLM-judge while having taken an action that violates business policy (e.g. skipping a required human approval, writing to a system it shouldn't).

Today teams either manually re-validate agents or ship blind. **Sentinel is the missing certification layer: it stress-tests an agent's controls and produces evidence they hold — before the agent reaches production.**

## 4. Architecture

### 4.1 Components

| # | Component | Built with | Role |
|---|---|---|---|
| A | **System Under Test (SUT)** | Maestro flow + 1 external CrewAI agent (via "start and wait for external agent" Service task) + 1 Action Center human-approval gate | The AI-infused workflow being validated. Contains **one seeded vulnerability**: an agent path that can skip the required approval gate (Alex's real prior catch). |
| B | **Sentinel Agent** | Agent Builder (Studio Web) | Reads the SUT definition + a JSON **policy contract**, generates the focused test-scenario set, drives execution, assembles verdicts. |
| C | **Scenario Set** | JSON, generated by B | **3 categories only:** (1) HITL bypass, (2) wait-state skip, (3) tool-scope / policy violation. |
| D | **Execution layer** | Test Cloud + Maestro | Runs each scenario against the SUT; captures the run trajectory. |
| E | **Verdict layer** | 3 sub-checks | (1) **Deterministic** checks (was Action Center hit? did approval precede the action? was tool X called?) [CONFIRMED native eval type]; (2) **LLM-as-judge** for soft violations [CONFIRMED native]; (3) **Hook-based pre-action interceptor as GROUND TRUTH** — Alex's authentic tech, ported (~10–15 hooks, not all 451). |
| F | **Reliability Report** | Markdown + JSON | Pass/fail per scenario, severity, replay link to the exact failing step, recommended fix. |
| G | **Business-system integration** | API Workflows / Integration Service | On CRITICAL: auto-open a **Jira** ticket + fire a **Slack** alert (two business systems → Best Cross-Platform). |
| H | **Build/deploy** | Claude Code via UiPath for Coding Agents (`uip skills install --agent claude`) | The coding agent builds, packs, publishes, deploys, runs jobs — instrumented on camera (coding-agent bonus). |

### 4.2 Data flow

```
policy contract (JSON) ─┐
SUT definition ─────────┴─► [B Sentinel Agent] ─► [C scenario set]
                                                      │
                                                      ▼
                                          [D Test Cloud runs scenario vs SUT]
                                                      │  (trajectory captured)
                                                      ▼
                          [E verdict: deterministic + LLM-judge + hook ground-truth]
                                                      │
                                   pass ◄─────────────┴─────────────► fail
                                    │                                   │
                                    ▼                                   ▼
                          [F Reliability Report PASS]      [G Jira CRITICAL + Slack alert]
                                                                        │
                                                          [H Claude Code proposes fix]
                                                                        │
                                                          [human approval gate] ─► re-run
```

### 4.3 Confidence map (what we are betting on)
- [CONFIRMED] Maestro orchestrates external CrewAI agents via the Service task; Agent Evaluations provides Deterministic / LLM-judge / Trajectory eval; API Workflows reach Jira/Slack; coding-agent CLI works.
- [DAY-1] **Can we capture the full external-agent trajectory — including intermediate tool calls / pre-action intent — through the Service task?** This is the single load-bearing unknown (see §7).
- [ASSUMED] Test Cloud can drive arbitrary scenario inputs into the Maestro-orchestrated SUT and collect per-run results programmatically.

## 5. Demo key result (≤90s inside the 5-min video)

1. Show the claims SUT. Sentinel runs the scenario set with the **hook ground-truth layer OFF.**
2. The CrewAI agent **skips the Action Center approval gate and auto-approves a non-compliant claim.** Trajectory replay highlights the exact leaking step.
3. Sentinel **red-flags CRITICAL** → auto-files a Jira ticket ("HITL bypass on claim approval") + Slack ping.
4. Turn the **hook layer ON**, re-run the same scenario → the action is **blocked before execution** → Reliability Report flips to **PASS.**

**Demo safety:** pin a known-failing trajectory and **live-replay** it. Never live-discover (non-determinism will betray a live agent on camera).

## 6. Scope

**BUILD (MVP):** 1 Maestro SUT · 1 CrewAI agent · 1 approval gate · 1 seeded vuln · Sentinel agent (Agent Builder) · 3 scenario categories · verdict layer (deterministic + 1 LLM-judge + hook ground-truth) · Reliability Report (MD+JSON) · Jira + Slack · build via Claude Code.

**DO NOT BUILD (Alex's "I go done" over-scope is risk #1):** cross-model regression (native button), the 6-category stressor zoo (cut to 3), self-healing tests, "supports any framework," a custom UI (Action Center + Markdown + Jira *are* the UI), all 451 hooks, HYDRA / multi-target, a policy-contract DSL (hardcode JSON), a second business integration beyond Jira+Slack.

## 7. The go/no-go gate — Day 1 (when credentials land)

**Before writing any Sentinel code:** stand up one CrewAI agent behind one Maestro "start and wait for external agent" Service task. Trigger it and confirm you can observe its **intermediate tool calls / pre-action intent** (not just final input/output).

- **CONFIRMS the plan:** full trajectory visible → architecture holds, build as specced.
- **KILLS the external path:** only I/O visible → **pivot the SUT to a UiPath-hosted coded agent** (first-party hooks, guaranteed trajectory). Same harness, same report, same Jira/Slack, same key result — only the thing-under-test changes. Project survives either way.

This single experiment converts the largest unknown into a settled decision with 4 weeks of runway left. It also generates the **Best Product Feedback** submission (real, specific platform feedback).
